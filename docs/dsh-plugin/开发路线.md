# DSH 插件开发路线（调研结论）

> 目标：做出一个能跑的 DSH 插件 → 推到 GitHub 加 `dsh-plugin` topic → 用作品换生态位/API 额度。
> 来源：deepseek-ai/deepseek-harness 官方文档（MIT 开源，2026-08-13）。

## 一、核心认知：插件 = 一个 `apply` 函数

DSH 基于 Cordis，"一切皆插件"。最小插件就是一个导出 `apply(ctx)` 的模块：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'
export function apply(ctx: Context) {
  // 在这里注册能力：工具/事件/服务/UI
}
```

加载方式：`cordis.yml`（或 patch）里列一行 `name` 指向模块，框架调用 `apply(ctx)`。

## 二、三类能力（按需注入）

| 想做什么 | 写法 | 依赖注入 |
|---------|------|---------|
| 注册一个**工具**（模型可调用） | `ctx.tools.register(defineTool({...}))` | `inject: ['tools']` |
| 监听**事件** | `ctx.on('tools/result', ...)` | `inject: ['tools']` |
| 提供**服务** | 类插件 `extends Service` | 其他插件 `inject: ['你的服务名']` |

一切注册都**随插件卸载自动清理**（生命周期绑定），无需手动 removeListener。

## 三、做一个"工具插件"（最小可用）

```ts
// src/greet-tool.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet the named person.',
    parameters: {
      name: { type: 'string', required: true, description: 'Who to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

## 四、三种加载/发布方式（从易到难）

### 1. 本地 overlay（验证最快）
```yaml
# scratch/cordis.yml
- insert:
    - id: hello
      name: '/绝对路径/scratch/src/my-plugin.ts'   # 必须绝对路径
```
```sh
pnpm dsh web --patch ./scratch/cordis.yml   # 打开 http://127.0.0.1:3080
```

### 2. 组合包 bundle（可安装、可分发）⭐ 推荐
目录结构：
```
hello-plugin/
├── package.json       # 声明 dsh.bundle
├── cordis.patch.yml   # patch 层：- insert: - id: hello, name: '<包名>'
└── index.js           # 插件代码（用 JS，避免构建坑）
```
```json
// package.json
{
  "name": "dsh-hello-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```
```yaml
# cordis.patch.yml
- insert:
    - id: hello
      name: dsh-hello-plugin
```
本地安装验证：
```sh
dsh plugin --profile demo add ./hello-plugin
dsh --profile demo --dump-config   # 检查层已生效
dsh --profile demo                 # 启动
```

### 3. 从 GitHub 安装（分发免 npm）⭐ 适合我们
```sh
dsh plugin --profile demo add github:you/hello-plugin
```
注意：git 安装拉**源码**，作者必须提供 `prepare` 脚本（pnpm 安装后自动构建），用户需在 profile 的 `pnpm-workspace.yaml` 里授权 `allowBuilds`。

## 五、环境准备（Termux / 手机）

- 需要 Node.js ≥ 18 + pnpm（Termux 有 nodejs 包，可装）
- **轻路径**：不 clone 整个 8600 文件仓库，单独建 npm 项目依赖 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-tools`，本地编译验证后用 bundle/GitHub 方式发布
- **重路径**：clone 仓库 + `pnpm install`（手机上慢，建议有电脑用电脑）

## 七、我们的第一个插件选题建议

把 codex-mobile-pro 的一个真实能力封装成 dsh 工具。候选（按性价比）：
1. **中文交互/翻译工具**：模型输出前统一转中文（贴合项目"中文交互"卖点）
2. **skill 检索工具**：暴露 70 个 skills 的索引，让 DSH agent 能按名检索/复用
3. **移动端状态工具**：查询手机 Termux 环境状态（磁盘/内存/网络），补 DSH 移动端场景

原则：小、完整、能跑、能演示。先做出 #2 的最小版（一个列表工具）即可发布。
