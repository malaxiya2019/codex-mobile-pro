# 循环自测

目标：测试全绿（或每个失败都有确凿定性），不掩盖问题。

## 流程

1. **基线**
   - 跑全量测试：`flutter test`（或项目对应命令）
   - 记录 `+通过 -失败` 数字

2. **失败定性（关键步骤，不要跳过）**
   - 每个失败分三类：
     - **flaky**：时间戳/竞态/顺序依赖 → 重跑验证（最多 3 次），记录通过率
     - **环境依赖**：PRoot/模拟器/CI 与本地差异、无法构造的场景 → 说明构造条件，不当作代码 bug
     - **真实 bug**：断言失败且与代码逻辑相关 → 修复
   - 定性必须给出证据（日志、重跑次数、环境差异点）

3. **修复与回归**
   - 只修真实 bug，不动 flaky 测试本身的断言来「变绿」
   - 修完重跑相关测试 → 全量测试
   - 循环直到：全绿，或失败全部有确凿定性且与本次变更零交集

4. **报告**
   - 全量结果数字
   - 失败清单：测试名 + 类别 + 证据 + 是否与本次变更相关
   - 修改了哪些测试/代码（如有）

## 约束

- 禁止通过改断言/跳过测试/删除测试来掩盖失败
- flaky 测试要修根因（等稳定、消除竞态），修不了就如实标注
