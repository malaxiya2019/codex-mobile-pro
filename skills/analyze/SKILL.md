# 项目分析（只读）

目标：不修改任何代码，给出可验证的项目地图。

## 流程

1. **基线确认**
   - `git status --short`（必须干净或记录脏文件）
   - `git rev-parse HEAD`、`git branch --show-current`
   - `git log -5 --oneline`（近期变更）

2. **项目地图**
   - 顶层目录/文件清单（`ls`，排除 build/依赖目录）
   - 技术栈证据：`pubspec.yaml`/`package.json`/`Cargo.toml`/`go.mod` 等
   - 分层结构：源码目录按 feature/core/shared 归类，标注职责
   - 入口点：main 入口、路由表、初始化链

3. **依赖与调用关系**
   - 核心服务/Provider/管理器之间的依赖方向
   - 用调用链证据（grep 关键符号 + 文件:行号）说明，不凭印象

4. **近期变更上下文**
   - 最近提交各自改了什么（`git show --stat`）
   - 变更之间的依赖关系

## 输出格式

- 项目一句话定位
- 分层/模块地图（目录 → 职责）
- 关键符号表（符号 → 文件:行 → 职责）
- 近期变更时间线
- 每个结论附证据路径

## 约束

- 全程只读：不修改、不格式化、不安装依赖
- 结论必须带文件证据（`文件:行号`），没有证据的标注「未验证」
- 不猜测：读不到就说读不到
