# 查证式研究

目标：每个结论都能被复现验证，无法验证的明确说「未验证」。

## 证据类型（按可信度排序）

1. **官方文档**：框架/厂商文档（如 Flutter 官方、GitHub Docs）——通过文档查询工具或直接抓取，保留来源 URL
2. **实测输出**：真实执行命令的输出（API 响应、CLI 结果、构建日志）——保留命令 + 输出
3. **本地历史**：git log、代码注释、之前修复记录——保留 commit SHA / 文件:行号
4. **推断**：无直接证据的推理——必须标注「推断」

## 流程

1. **提取断言**：把要查证的结论列成清单，每条对应一个问题
2. **逐条查证**
   - 官方文档优先（查库/查官网）
   - 能实测的就实测（curl/CLI/git 命令），记录原始输出
   - 本地历史证据（git blame/log/注释）注明出处
3. **留档**：每条证据给「复现命令」，让任何人都能重新验证
4. **输出证据清单**
   - 证据 ID → 结论 → 证据类型 → 来源 → 复现命令
   - 未验证的结论单列「未验证」并说明缺什么证据

## 约束

- 不编造来源：没查过的链接不能写
- 二手信息（博客/问答）降级使用，标注来源类型
- 结论与证据一一对应，证据不足就写「证据不足」
