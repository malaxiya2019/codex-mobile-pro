# 需求访谈

目标：在动手前消除歧义，避免脑补。

## 流程

1. **识别歧义点**
   - 范围（改哪些文件/模块）
   - 是否允许修改代码（只读审计 vs 实施）
   - 输出格式（报告/代码/清单）
   - 验收标准（怎样算完成）
   - 风险边界（哪些模块禁止触碰）

2. **提问规则**
   - 最多 3 问，每问给 2–3 个互斥选项，推荐项放第一位
   - 每个选项附一句影响说明
   - 一次问完，不挤牙膏

3. **无答复时**
   - 声明默认假设（最保守的选项：只读、最小范围、分步输出）
   - 继续执行并记录假设，最后报告里列出所有假设
   - 绝不把猜测当需求

## 输出格式

- 3 个问题 + 用户答复（或「未答复 → 采用默认假设」）
- 明确的需求边界清单（做/不做/禁止做）

## 约束

- 不问可以自己查证的问题（如仓库结构、技术栈）
- 只问影响方向的决策问题
